# Непрерывное улучшение процессов доставки (Модуль А)

Конфигурация: ЦВБ_Межрегион (1С:Предприятие 8.5.1.1150, режим совместимости Version8_5_1).
Документ относится к разделу «Непрерывное улучшение» Модуля А (1,25 балла).

## 1. Текущий процесс и потери (Lean)

Процесс «приём заказа → передача курьеру → доставка → закрытие» до внедрения конфигурации
выполняется вручную: заказ фиксируется в таблице или на бумаге, цена блюда уточняется у повара или
по прайсу, курьер подбирается по телефону, статус курьера не виден диспетчеру, время доставки считается
вручную. Ниже потери по классической классификации Lean (муда), которые устраняет или сокращает конфигурация.

| Вид потерь | Где проявляется в процессе | Как решено в конфигурации |
|---|---|---|
| Ожидание | Диспетчер ждёт, пока освободится курьер, и не видит, кто свободен | Справочник Курьеры со статусом (Свободен / Занят / НеНаСмене) и список курьеров в АРМ с очередью заказов |
| Перепроизводство | Заказы принимаются без проверки состава и минимальной суммы, на кухню уходят лишние позиции | Проверка минимальной суммы ресторана (предупреждение) и блюд одного ресторана (отказ) перед записью |
| Лишние движения | Поиск клиента, адреса, цены и курьера в разных местах | Автозаполнение адреса по клиенту, цена блюда из регистра ЦеныБлюд, назначение курьера из АРМ без карточки |
| Транспортировка (передача информации) | Информация о заказе передаётся устно или по мессенджеру | Единый документ Заказ и АРМ диспетчера с динамическим списком активных заказов |
| Избыточная обработка | Сумма заказа и время доставки считаются вручную | Сумма = Количество × Цена, СуммаДокумента, ВремяДоставкиМинут рассчитываются автоматически |
| Запасы (незавершённые заказы) | Заказы, которые ждут курьера, теряются из вида | Отбор АРМ по статусам Новый / Готовится / ПереданКурьеру и условное оформление по статусам |
| Дефекты | Ошибки в адресе, блюде, курьере, времени | Обязательные поля (Клиент, Ресторан, Телефон, Адрес), проверки при записи, отчёты для контроля |
| Неиспользованный потенциал сотрудников | Аналитика по блюдам и курьерам не ведётся | Отчёты ОтчетПоЗаказам, ОтчетПоРесторанам, ОтчетПоКурьерам, ПопулярностьБлюд |

## 2. Целевой показатель АРМ диспетчера

Целевая оценка: назначение курьера на заказ сокращается с **около 5 минут до около 15 секунд**.

Это проектная оценка, а не результат замера. Она основана на следующей логике:

- до внедрения диспетчер звонит курьерам, уточняет, кто свободен, открывает карточку заказа,
  выбирает курьера и сохраняет документ (несколько переходов и ожидание ответа);
- в АРМ диспетчера список активных заказов и список курьеров с их статусами и очередью находятся
  на одном экране; назначение выполняется одной командой «Назначить курьера на заказ» без открытия
  карточки и без модальных окон;
- статус курьера (Занят) и статус заказа (ПереданКурьеру) меняются автоматически при назначении.

Перед принятием решения целевую оценку необходимо проверить замером на пилотных сменах
(хронометраж 20–30 назначений «до» и «после»).

## 3. Прорывные предложения

1. **Автоподбор курьера по очереди и транспорту.** Система предлагает курьера с минимальной очередью
   среди статусов Свободен или Занят с учётом типа транспорта (пеший / велосипед / автомобиль) и
   расстояния до ресторана. Данные для расчёта уже есть: статус, тип транспорта и очередь заказов.
2. **Прогноз загрузки по популярности блюд.** Отчёт ПопулярностьБлюд по дням недели и часам
   позволяет планировать смены курьеров и объём закупок. Снижается риск перепроизводства и задержек
   при пиковом спросе.
3. **Автоматические уведомления о статусах.** При переходе заказа в статус ПереданКурьеру и Доставлен
   отправляется сообщение клиенту на телефон из справочника Клиенты. Это снижает количество входящих
   звонков диспетчеру и дает клиенту актуальное время доставки (ПлановоеВремяДоставки).

## 4. Показатели для контроля

| Показатель | Источник | Периодичность |
|---|---|---|
| Среднее время доставки, мин | ОтчетПоКурьерам (СреднееВремяДоставкиМин) | еженедельно |
| Количество выполненных доставок по курьерам | ОтчетПоКурьерам (ВыполненоДоставок) | еженедельно |
| Сумма продаж по ресторанам | ОтчетПоРесторанам (ОбщаяСуммаПродаж) | ежемесячно |
| Доля блюда в общем количестве заказанных | ПопулярностьБлюд (ДоляОтОбщегоКоличества) | ежемесячно |
| Время назначения курьера, с | Хронометраж на АРМ диспетчера | при пилоте и после внедрения |

## 5. План внедрения

1. Пилот на одном ресторане и 2–3 курьерах в течение одной недели.
2. Хронометраж назначения курьера «до» и «после» и сравнение с целевой оценкой из раздела 2.
3. Корректировка отборов АРМ и условного оформления по замечаниям диспетчеров.
4. Тиражирование на все рестораны и включение отчётов в еженедельный разбор.
5. Постепенное внедрение предложений раздела 3 после подтверждения эффекта от базовой автоматизации.
